  Setup: same recipe (lr=2e-4, 5 epochs, r=16/α=32, decode hardening),
         same 32-row holdout, only the train set differs.

  Train sizes:  v3 165  → v4 185 (+20 imbalanced)
                         → v5 241 (+56 defer-class-balanced)

  Metric                    v3        v4        v5        v3 vs v5
  ------------------------  --------  --------  --------  --------
  exact_action_agreement    0.844     0.781     0.688     -0.156  ← regression
  score_mae (lower better)  0.055     0.066     0.084     +0.029  ← worse
  useful_agreement          0.688     0.656     0.812     +0.124  ← improved (binary)
  parse_rate                1.000     1.000     1.000     +0.000

  Per-class:
    accept   1.000  →  1.000  →  1.000   (saturated)
    refine   1.000  →  1.000  →  0.875
    defer    0.625  →  0.500  →  0.625
    skip     0.750  →  0.625  →  0.250   ← v5 cratered

  Diagnosis:
    v4: +20 train rows were class-imbalanced (refine + accept only).
        Hurt minority classes that were already hardest.
    v5: +56 train rows were defer-class-balanced (17 defer + 1 skip).
        Defer didn't lift; skip cratered. Model over-shifted toward
        defer at skip's expense in borderline cases.

  Two consecutive negatives on +data.

  Decision:  v3 retained as canonical. Neither v4 nor v5 promoted.

  Architectural lesson:
    Static corpus expansion has hit the inflection point on this
    architecture / holdout combination. The next lift comes from
    runtime TTT under the six viability gates — exactly what the
    submission's central claim says.
