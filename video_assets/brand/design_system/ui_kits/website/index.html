SimSat.

On-orbit inference, continually refined by operator-labelled JSON within uplink bandwidth parameters — governed by six non-compensatory viability gates.

01 — The architecture

The architecture is the contribution.

A satellite has minutes, not hours, between encounter windows. The next window arrives in minutes; sensor distributions drift between them. SimSat decides on-orbit and refines through what it can ferry: operator-labelled JSON within uplink bandwidth parameters.

The same pipeline you would deploy on-orbit runs the demo here. It chooses an action — accept, refine, defer, skip — and writes a receipt. Six viability gates rule on each potential update before any weight moves.

03 — The convention

Six gates. No averaging.

A viable update is one that passes every gate. The gates do not vote. They are not compensatory. Any single block ends the update; the trace persists.

01information_gainWill the update teach anything new?
02observation_qualityIs the input good enough to learn from?
03metadata_consistencyDo the receipts agree with each other?
04update_magnitudeIs the proposed delta within bounds?
05update_rateAre we updating too quickly to recover?
06error_balanceAre recent errors balanced or skewing?

Operator action

The operator decides. SimSat proposes. The trust layer challenges. The operator overrides — and the override becomes the next training row.

Every action ships with a JSON receipt: trace id, sensor, cloud, gate verdict, lora_delta, reviewer.
